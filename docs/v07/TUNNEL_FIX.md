# V0.7 · 隧道穿模原因与修复记录（P0）

## 1. 用户报告的现象

车辆在马路上行驶时会**直接穿入隧道内部**，道路与隧道空间发生穿模。用户要求 P0 彻底修复，
并明确：不能只靠限制相机掩盖、不能只靠静态射线测试、自动化通过但画面仍穿模即判定失败。

## 2. 复现（真实浏览器，非静态推测）

`tools/diagnose.cjs` 在真实无头 Chromium 中加载 **GitHub 最新 `main` 上的 V0.6 页面**
（`baseline/explore-v06.html`，84 414 B，与线上 SHA256 一致），暂停主循环后逐帧调用
`drive(dt)`，记录 `state` 与 `tunnelAt()` 结果并在关键帧截图。

- `evidence/V06-BEFORE-ROOT-CAUSE.json`：61 个采样点中 **6 个低层道路点被误判为「在高空隧道内部」**。
  最坏样本：`x=163.7, z=159.9, y=15.6`，却被判定 `lat=-58.6`、`y0=93`、`k=10`。
  横向偏出 58.6 m、高差约 77 m，仍被认定为洞内。
- `evidence/V06-BEFORE-TRACE.json`：车从 `y=39.7` 被拉到 `y=90.2` 再到 `y=94.1`，
  `ti.inside=true`、`y0=93.23` —— 从低层马路被搬进 93 m 高空的隧道。
- `evidence/V06-BEFORE-drive-00.png` / `-10.png`：低层马路上方悬着黑色「天路」，
  车辆随后出现在纯色拱顶的洞内。

## 3. 根因

V0.6 的 `tunnelAt(x,z)` 只做 2D 最近轴点判定：

```js
if(!best||best.d2>3600)return null;      // 60 m 邻域内即视为「洞附近」
...
return { ..., inside:k>0&&k<t.axis.length-1 };
```

它**完全不检查横向距离 `lat` 和高程 `y`**。V0.6 路网是多层螺旋盘山线，
高程从 1 m 到 99 m 立体回环，低层公路在平面上恰好经过高层隧道轴线附近，
于是被判为洞内。随后 `clampIntoTunnel(nx,nz,ti)` 会强行把车搬回洞轴：

```js
const lim=ti.W/2-3.1,lat=clamp(ti.lat,-lim,lim),along=ti.along,a=ti.a;
return [a.x+a.nx*lat+a.nz*along, a.z+a.nz*lat-a.nx*along];
```

这就是「从马路直接穿入隧道内部」的直接原因。附带的结构问题：V0.6 在隧道段
挖空主路并另铺一层 deck，存在**两层重叠路面**；多层螺旋还造成视觉上悬空的黑色天路。

## 4. V0.7 修复

| # | 修复 | 文件 |
| --- | --- | --- |
| 1 | 取消螺旋盘山，改为单层 2D 不自交、高程单调升→平→降的「穿山公路」（18 控制点，1→66→1 m） | `src/02-roads.js` |
| 2 | `tunnelAt(x,z,y)` 改为按轴向线段插值，返回 `inLat` / `inAlong` / `inY` 与带符号 `u`；洞口前 `u<0`、出口后 `u>rings`，洞外不再提前变暗或误判 | `src/02-roads.js` |
| 3 | `drawRoad()` 只生成一条连续路面；`tunnelProfile()` 只生成侧壁 + 拱顶，**不封底**，杜绝双层路面 | `src/02-roads.js`, `src/06-tunnel.js` |
| 4 | 删除 `clampIntoTunnel()`；改为 `softTunnelGuide()`，车身半宽 `CAR_HALF_W=2.45`，把 `\|lat\|` 约束到 `W/2-2.45-0.9`，单帧修正 ≤1.2 m，不瞬移、不吸车 | `src/10-car.js` |
| 5 | 洞口前 18 环「引道车道渐进收窄对准」+ 洞口前高程外插，斜向驶来的车在到达洞口前已收进净空 | `src/10-car.js`, `src/02-roads.js` |
| 6 | 洞内相机用「相机所在环」的 `y0` 定高，避免上坡隧道里相机顶进拱顶；三视角统一收进洞轴并强制钳制目标与结果 | `src/11-camera.js` |
| 7 | `state.tunnelBlend` 按轴向进度 `u` 过渡，而非 2D 半径 | `src/10-car.js` |

**关键原则**：相机钳制只在严格 3D 洞内生效，且车辆的碰撞约束是独立逻辑；
没有用「把相机固定在洞内」来掩盖车辆穿模。

## 5. 逐帧驾驶验收

`tools/drivetest.cjs` 暂停主 rAF，逐帧调用 `drive(1/60)` + `cameraUpdate(1/60)`，
每个抽样段渲染并截图；违规判定使用**车辆碰撞体**（`|lat| + 2.45 > W/2 - 0.15`）
而非仅比较中心点。

结果：`evidence/V07-DRIVE-SUMMARY.json`，**`OVERALL_PASS true`，`PAGE_ERRORS 0`**，
共 **4680 帧 / 107 张关键帧截图**。

## 6. 画面复核（自动化通过后仍逐张看图）

按用户要求「若自动化测试通过但画面仍出现穿模，判定失败」，数值通过后继续做了多轮画面复核，
并据此修掉了以下真实可见问题：

| 发现 | 定位方法 | 修复 |
| --- | --- | --- |
| 洞内中段整屏被石纹遮挡 | 相机中心 1.3 m / 0.6 m 命中 `tunnel-inner`（上坡隧道相机顶进拱顶） | 相机高度改用所在环 `y0`，三视角统一收进洞轴 |
| 旁路首帧巨大纯黑三角 | 逐类隐藏实验：`portal-mass` 背面 | 洞口立面改不受光照的 `MeshBasicMaterial` 岩纹 |
| 第二 / 第三视角整屏岩纹 | 相机侧偏 17 m 进山体 | 洞内三视角不再侧向偏移，并强制钳制插值目标 |
| 远景三片「漂浮纸片」 | 逐类隐藏实验：`far-town` / `far-roofs` 是两片各自随机的竖直平面且用绝对高度 | 改为有体积、落地（y=.5）的低面数小屋 + 双坡顶 + 聚成 4 组村落 + 柏树围合 |
| 小镇横贯全屏的黑色粗绳 | `MAT.iron` 跨街绳 | 改浅石色细绳，彩旗尺寸收敛 |
| 出口后「纸片」贴脸 | 洞口名牌/纹章旗与门楣相互穿插 | 名牌移到门楣正面、纹章旗补旗杆落地 |
| 斜跨整条路面的灰色长带 | 洞口跳点处 `Batch.add` 把 ribbon 断点前后硬连 | 引道挡墙按连续段收集，洞口段断开 |
| 名牌只剩空白半框、文字被遮 | 射线诊断：`BoxGeometry` 在名牌前 2.6 m | 门楣旋转角由 `atan2(nx,nz)` 修正为 `atan2(-nz,nx)`（24.5 m 长条原被转到轴向） |
| 湖畔完全看不到水面 | 地面抬到 y=.45 而水面仍是 y=-.7 | 水面/浅滩/岸线/卵石/芦苇统一抬到地面之上 |

最终复核画面：`previews/01..06`、`previews/13-精品岛俯瞰.png`、
`evidence/drive/03-diagonal-02/04/05.png`、`08-bypass-00.png`、`09-lowroad-04.png`、
`cam-mode-0/1/2.png` —— 车辆在连续路面上、洞壁/拱顶/路面连续、无悬空天路、
无两层重叠路面、无黑面与漂浮纸片。

## 7. 仍需注意

- 上述驾驶验证是**真实无头 Chromium 逐帧调用 `drive()` + `cameraUpdate()` 并渲染截图**，
  不是静态射线测试；但它仍是桌面软件渲染环境，**不等价于真机触控驾驶**。
- P0 判定为通过，仅针对本次 9 场景、3 视角、4680 帧与已复核画面；
  真机长时间试玩仍需用户实测确认。
